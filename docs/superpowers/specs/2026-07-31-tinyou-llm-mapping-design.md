# 티뉴 — LLM 파츠 매핑 설계 스펙 (Plan 3.5 애든덤)

- 날짜: 2026-07-31
- 상태: 승인됨 (사용자가 "A. LLM 파츠 매핑" 선택)
- 전제: Plan 3 머지 완료 상태의 main. 아바타 v2(12종×8팔레트) 렌더 시스템은 유지하고 **종·팔레트 선택 로직만 LLM으로 교체**한다
- 배경: 실사용 피드백 — "캐릭터가 다 똑같이 생겼고, 색깔 키워드가 아니라 전체 문장으로 파악해줘". 진단 결과 실제 답변 3건 중 1건이 사전 매칭 실패(해시 폴백), 2건이 표면 키워드 오매칭

## 결정

- **모델**: Claude Haiku 4.5 (`claude-haiku-4-5`, $1/$5 per MTok). 생성 1회당 입력 ~400·출력 ~50토큰 → 약 1원 미만
- **호출 위치**: 새 Supabase Edge Function `map-avatar` (Deno). API 키는 `supabase secrets set ANTHROPIC_API_KEY=...`로만 저장 — 클라이언트·레포에 절대 노출 금지
- **출력 강제**: Messages API 구조화 출력(`output_config.format`, json_schema) — `{ species: enum(12종), palette: enum(8팔레트) }`. 파싱 실패가 원천적으로 없음
- **호출 시점**: 질문 카드 작성 완료 → "분신 만나러 가기" 클릭 시 1회. "다시 뽑기"는 기존대로 로컬 salt 변형(종·팔레트 고정, 표정·소품만 변화) — 추가 호출 없음
- **폴백**: Edge Function 실패(네트워크·API 장애·키 미설정) 시 기존 사전 매칭+해시로 자연 강등. 매핑은 향상이지 의존성이 아님(Realtime과 동일 원칙)
- **재현성**: 확정 시 `avatar_seed`에 `{ answers, salt, mapping: {species, palette} }`로 저장. 이후 재렌더는 LLM 재호출 없이 mapping을 그대로 사용 → 모델이 바뀌어도 캐릭터 불변
- **시그니처**: `generateAvatar(answers, salt, mapping?)` — mapping이 유효하면 종·팔레트를 override, 없으면 기존 로직. 순수 함수·결정성 유지
- **보안**: map-avatar는 로그인 사용자만(JWT 검증), 답변 합계 2,000자 제한. 답변 원문은 로그에 남기지 않는다(연인 묘사 = 프라이버시)

## 프롬프트 원칙

- 시스템 프롬프트에 12종 키·8팔레트 키와 각각의 한 줄 성격 설명(예: bear=듬직·포근·큰 덩치, lemon=노랑·밝음·병아리색)을 제시
- "키워드 표면 매칭이 아니라 인물 묘사 전체의 인상으로 가장 어울리는 동물과 색을 고르라"고 지시
- 답변이 동물을 직접 지목하면(예: "햄스터 같아") 그 동물을 우선한다

## 스코프 밖 (별도 트랙)

- 도트 다듬기 라운드("못생겼어" 절반) — Plan 4 백로그 유지
- 표정·소품 힌트의 LLM 선택 — v1은 종·팔레트만, 효과 확인 후 확장

## 성공 기준

1. 사전에 없는 문장(예: "겨울잠 잘 것 같고 안기면 포근한 사람")으로 곰이 나온다
2. "다시 뽑기"를 눌러도 종·팔레트가 유지된다
3. Edge Function을 끄면(키 제거) 기존 사전+해시 동작으로 강등되어 생성이 계속 된다
4. avatar_seed로 저장된 기존 캐릭터·신규 캐릭터 모두 재렌더가 결정적이다
