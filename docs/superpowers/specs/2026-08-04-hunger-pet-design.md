# 배고픔 지수 + 무한 쓰다듬기 설계 (2026-08-04)

## 배경 / 목표

현재 돌봄 액션(밥·쓰다듬기·굿나잇)은 `canCareToday`로 종류별 하루 1회 제한, XP는 기록당
10 고정이다. 이 설계는 두 가지를 바꾼다:

1. **배고픔 지수**: 밥주기를 "하루 1회"에서 "배고플 때만"으로 바꿔 하루 두 끼 리듬을 만든다.
   연출 + 밥 타이밍 게이트 역할만 하며 벌점은 없다 (절대 죽지 않음 철학 유지).
2. **무한 쓰다듬기 + 실시간 알림**: 쓰다듬기는 하루 2회만 XP가 쌓이고, 그 이후로는
   무제한으로 쓰다듬을 수 있다. 쓰다듬을 때마다 상대에게 앱 내 실시간 토스트가 간다.

기존 원칙 준수: 서버 크론 없음(모든 상태는 타임스탬프 파생 계산).

**스키마 변경 1건 필요** (설계 검증 중 발견): `care_actions`의
`unique (character_id, user_id, type, care_date)` 제약이 하루 1회를 DB 레벨에서
강제하고 있어, 밥 2회·쓰다듬 2회를 허용하려면 이 제약을 제거해야 한다.
굿나잇은 하루 1회 유지가 필요하므로 **굿나잇 전용 부분 유니크 인덱스**
(`where type = 'goodnight'`)로 교체한다. 밥·쓰다듬의 하루 상한은 클라이언트
파생 계산이 담당한다 (5절 신뢰 모델과 동일 — 커플 앱 특성상 수용).

## 1. 배고픔 지수

### 도메인 (`src/domain/hunger.ts` 신규)

`happiness.ts`와 같은 파생 계산 패턴.

- `type HungerLevel = 'full' | 'ok' | 'hungry'`
- `hungerFrom(lastFedAt: Date | null, now: Date): HungerLevel`
  - `null`(밥 기록 없음) → `hungry` — 첫 밥은 바로 가능
  - 마지막 밥 후 4시간 미만 → `full`
  - 4시간 이상 8시간 미만 → `ok`
  - 8시간 이상 → `hungry` (최대 단계 — 더 나빠지지 않음)
- `lastFedAt`은 careLog의 `feed` 액션 중 최신 `createdAt`에서 유도.
  타임스탬프는 서버(Supabase) 기록이므로 로컬 시계 조작으로 우회 불가.

### 게이트 변경

- 밥: `canCareToday` 대신 **`hungry`일 때만 가능**. 8시간 간격이라 실질 하루 2회
  (두 끼 리듬: 아침/저녁. 이론상 자정 직후 시작하면 달력일 기준 3회까지 가능하나
  수면 리듬상 드물고, 허용해도 문제없어 별도 캡을 두지 않는다).
- 굿나잇: 기존 하루 1회 유지 (변경 없음).

### 연출 / UI

- 스테이지에 배고픔 3단계 표시 (밥그릇 아이콘 등).
- `hungry`일 때 이따금 꼬르륵 연출 (말풍선/파티클 — 기존 FSM 상태 재사용, 신규 상태 없음).
- 배부를 때 밥 버튼 비활성 + "아직 배불러요 (약 N시간 후)" 안내.
- 밥 주면 기존 eat → happy 시퀀스 그대로.

## 2. 쓰다듬기: 2회 스택 + 무한 쓰다듬기

- `canPetStackToday(actions, userId, now)`: 오늘(서울 기준) 기록된 `pet`이 2회 미만인가.
- 스택이 남아 있으면: 기존처럼 `care_actions`에 기록 → XP +10.
- 스택 소진 후: **쓰다듬기는 계속 가능**하되 DB에 기록하지 않는다 — 로컬 petted
  애니메이션만 재생. (DB가 연타로 불어나지 않고, `xpFromActions` = 기록 수 × 10
  계산식도 그대로 유지된다.)
- 쓰다듬 버튼은 항상 활성. 스택이 남았을 때만 +10 XP 이펙트 표시, 소진 후엔 하트만.

## 3. 쓰다듬 실시간 토스트 (앱 내)

- **송신**: 스택 여부와 무관하게 쓰다듬을 때마다 기존 커플 Realtime 채널
  (`useCoupleChannel`)로 broadcast 이벤트 전송: `{ event: 'pet', nickname }`.
  (기록되는 스택 쓰다듬도 postgres_changes와 별개로 broadcast를 보낸다 —
  토스트는 broadcast 단일 경로로만 처리해 이중 발화를 피한다.)
- **수신**: 30초 병합 윈도 —
  - 첫 이벤트: "{nickname}님이 쓰다듬었어요 🥰" 토스트 즉시 표시
  - 윈도 내 추가 이벤트: 새 토스트를 띄우지 않고 문구를
    "{nickname}님이 잔뜩 쓰다듬고 있어요 🥰"로 교체 (연타 스팸 방지)
  - 병합 로직은 순수 함수로 분리해 유닛 테스트한다.
- **상대가 앱을 꺼둔 경우**: 다음 접속 때 기존 TraceToast 요약으로 확인.
  (요약은 기록된 스택 쓰다듬 최대 2회만 집계된다 — 의도된 동작.)
- OS 푸시(Web Push)는 이번 범위에서 제외 — `notes/next-steps.md`에 추후 작업으로 기록.

## 4. XP / 레벨

- 기록당 10 XP 계산식 무변경.
- 하루 XP 상한: 30 → **통상 50** (밥 2 + 쓰다듬 2 + 굿나잇 1. 밥 3회 엣지에선 60).
  레벨 커브는 건드리지 않는다.

## 5. 에러/엣지 케이스

- 배고픔·스택 판정은 클라이언트 파생 계산이므로 조작된 클라이언트가 `care_actions`를
  직접 insert하면 우회 가능 — 기존 `canCareToday`도 동일한 신뢰 모델(RLS는 커플 범위만
  보장)이므로 이번 범위에서는 그대로 둔다. 커플 앱 특성상 실질 리스크 낮음.
- 자정(서울) 경계: 스택 카운트는 `dateKeySeoul` 재사용. 배고픔은 날짜와 무관한 경과
  시간 기준이므로 자정 영향 없음.
- broadcast 유실(상대 순간 오프라인): 토스트는 best-effort. 기록된 스택 쓰다듬은
  TraceToast가 보정한다.
